# Aircraft Data Providers for Signalwatch

**Research date:** 2026-09-30  
**Depth:** Standard  
**Sources consulted:** 29  
**Scope:** Current provider access, query shape, data, limits, rights, and Replit-workspace reachability. Research only; no app code, keys, provider contact, or deployment changes.

## Executive summary

**Do not integrate ADSB.lol yet.** Its official OpenAPI documents free GET access, bounded point/closest queries up to 250 nautical miles, ODbL 1.0 for the API and public data, a future feeder-linked API key, and a request that production users contact the operator. The official API README says rate limits vary with environment load but gives no numeric quota or burst limit. One unauthenticated point query from the research workspace returned HTTP 200 with no aircraft. These facts establish a documented query path and one observed connection—not permission for Signalwatch’s public display, normalization, caching, automated refresh, or Replit-hosted production use. The ODbL distinguishes public use of Produced Works from share-alike duties for Derivative Databases, but the inspected sources do not classify Signalwatch’s proposed data handling. **Decision: Provider confirmation required.** [[1]](https://api.adsb.lol/api/openapi.json) [[2]](https://www.adsb.lol/docs/open-data/api/) [[3]](https://api.adsb.lol/v2/point/51.5/-0.1/10) [[4]](https://www.adsb.lol/privacy-license/) [[5]](https://opendatacommons.org/licenses/odbl/summary/) [[6]](https://opendatacommons.org/licenses/odbl/1-0/) [[27]](https://raw.githubusercontent.com/adsblol/api/main/README.md)

The other candidates have material gates. Airplanes.live’s API base returned 403 with a request to contact the provider; its docs and terms were blocked, so its API contract and rights remain unknown. OpenSky documents anonymous access and quotas, but a geographic API request timed out from this workspace, its README warns about hyperscaler blocks, and its terms could not be reviewed. adsb.fi’s official API contract and terms remain unverified. ADS-B Exchange has a documented radius API and published rate tiers, but requires an API key; the OpenAPI and official sample disagree on the key header, and its AUP bars distribution absent written authorization. The OpenAPI also links a separate terms page. [[7]](https://api.airplanes.live/) [[8]](https://airplanes.live/api-docs/) [[9]](https://airplanes.live/get-started/) [[10]](https://airplanes.live/terms/) [[11]](https://openskynetwork.github.io/opensky-api/rest.html) [[12]](https://raw.githubusercontent.com/openskynetwork/opensky-api/master/README.md) [[13]](https://opensky-network.org/about/terms-of-use) [[14]](https://opensky-network.org/api/states/all?lamin=51.45&lomin=-0.15&lamax=51.55&lomax=0.05) [[15]](https://adsb.fi/) [[16]](https://api.adsb.fi/) [[17]](https://www.adsbexchange.com/data-products/) [[18]](https://gateway.adsbexchange.com/api/aircraft/v2/docs/openapi.json) [[19]](https://gateway.adsbexchange.com/api/aircraft/v2/lat/37.77/lon/-122.42/dist/10) [[20]](https://www.adsbexchange.com/data-products/sample-api-call/) [[21]](https://www.adsbexchange.com/acceptable-use-policy/) [[22]](https://www.adsbexchange.com/terms-of-use/)

FAA SWIM offers near-real-time U.S. aviation data through a separate Solace JMS access path, not a verified anonymous REST feed. FlightAware is a commercial, usage-based candidate whose Standard tier describes derivative-work distribution for business-to-consumer use, but the sources reviewed did not establish a geographic point/radius query, Signalwatch-specific permission, or a simple request-rate cap. [[23]](https://www.faa.gov/air_traffic/technology/swim) [[24]](https://www.faa.gov/air_traffic/technology/swim/products/get_connected) [[25]](https://www.flightaware.com/commercial/aeroapi/) [[26]](https://www.flightaware.com/aeroapi/portal/documentation)

## ADSB.lol Terms & Access Verification

The labels below distinguish facts in the inspected source text or a single observed request from legal or production clearance. The research service’s HTTP 402 errors were tool-service failures; they are not ADSB.lol access responses. Direct first-party HTTPS captures were inspected and saved in `research/sources/`.

### Access and operational terms

The official contract describes GET requests to the API base `https://api.adsb.lol`, including `/v2/point/{lat}/{lon}/{radius}`, the equivalent `/v2/lat/{lat}/lon/{lon}/dist/{radius}` form, and `/v2/closest/{lat}/{lon}/{radius}`. The bounded radius is 0–250 nautical miles. The OpenAPI says current API use is free, asks production users to contact the operator, and says an API key will be required in the future and can be obtained by feeding. The docs say the API is available to everyone; neither the docs nor contract specifies an account prerequisite or current key header. One unauthenticated point request from the research workspace returned HTTP 200, with an empty aircraft list. This is a single reachability observation, not evidence of production approval or API-server egress. [[1]](https://api.adsb.lol/api/openapi.json) [[2]](https://www.adsb.lol/docs/open-data/api/) [[3]](https://api.adsb.lol/v2/point/51.5/-0.1/10)

The official API README says rate limits are dynamic based on environment load. It publishes no numeric requests-per-minute limit, daily quota, burst allowance, per-IP/key rules, or supported polling interval. The privacy/license page provides the service “as is” and disclaims warranties for accuracy, timeliness, completeness, reliability, and availability. The API schema exposes `seen`, `seen_pos`, `mlat`, and `tisb`, but the inspected API contract and model provide no field-unit definitions, stale threshold, expiry policy, or freshness SLA. The feed README lists ADS-B, UAT, MLAT, ACARS, and VDL2 as feeder/input modalities; that does not establish geographic coverage or that every modality appears in public API responses. [[4]](https://www.adsb.lol/privacy-license/) [[27]](https://raw.githubusercontent.com/adsblol/api/main/README.md) [[28]](https://raw.githubusercontent.com/adsblol/feed/master/README.md) [[29]](https://raw.githubusercontent.com/adsblol/api/main/src/adsb_api/utils/models.py)

### Public display and ODbL

ADSB.lol identifies its API and all public data as ODbL 1.0. Its privacy/license page’s separate CC0 statement applies to data sent to its feeder endpoints; it is not a CC0 grant for public API responses. No inspected ADSB.lol page states a standalone policy for third-party public maps, normalized records, periodic automated refresh, short-lived caches, or Replit/cloud-hosted consumers. [[1]](https://api.adsb.lol/api/openapi.json) [[4]](https://www.adsb.lol/privacy-license/)

The ODbL full text—not its expressly non-controlling summary—distinguishes a Database, Derivative Database, and Produced Work. Section 3.1 grants licensed use of the database, including commercial use and public display, subject to the license. Section 4.3 specifies a source/license notice when a Produced Work is publicly used; sections 4.4(a)–(c) set conditions for public use of a Derivative Database, including share-alike, and section 4.5(b) says creating a Produced Work does not by itself create a Derivative Database. Section 2.4 also distinguishes database rights from rights in individual contents. These are the license’s stated categories and provisions, not a conclusion about Signalwatch. Whether the queried records, normalized map, or retained observations fall into a particular category—and whether the returned records are covered as licensed contents—remains unresolved. [[5]](https://opendatacommons.org/licenses/odbl/summary/) [[6]](https://opendatacommons.org/licenses/odbl/1-0/)

- The official README says rate limits vary with environment load; no numeric limit or polling allowance was found in the inspected contract, docs, or README. [[27]](https://raw.githubusercontent.com/adsblol/api/main/README.md) [[1]](https://api.adsb.lol/api/openapi.json) [[2]](https://www.adsb.lol/docs/open-data/api/)
- The provider disclaims a timeliness or availability warranty and publishes `info [at] adsb.lol` as its contact email. The feeder CC0 statement is distinct from public API ODbL. [[4]](https://www.adsb.lol/privacy-license/)
- The ODbL text contains separate rules for Database conveyance, Produced Work notices, and publicly used Derivative Databases; it does not itself classify Signalwatch’s proposed implementation. [[6]](https://opendatacommons.org/licenses/odbl/1-0/)

- The API schema contains `seen`, `seen_pos`, `mlat`, and `tisb`; the inspected sources do not define their units, freshness meaning, or display implications. The feeder README describes input modalities, not what every API response contains. [[1]](https://api.adsb.lol/api/openapi.json) [[28]](https://raw.githubusercontent.com/adsblol/feed/master/README.md) [[29]](https://raw.githubusercontent.com/adsblol/api/main/src/adsb_api/utils/models.py)
- The provider documents public API data under ODbL 1.0, but no separate ADSB.lol terms clause explains public-display permission, exact UI attribution, or the licensing treatment of normalized and cached observations. [[1]](https://api.adsb.lol/api/openapi.json) [[4]](https://www.adsb.lol/privacy-license/)

### Unresolved

- Whether public display, periodic automated refresh, normalization, or short-lived caching by Signalwatch is permitted under the provider’s current production terms.
- Whether Signalwatch’s queried/normalized/stored records constitute ODbL Contents, a Produced Work, a Derivative Database, or another category; what share-alike or database-offer duties follow; and what exact attribution text, placement, database link, and license notice are required.
- Numeric request quotas, burst/per-IP/key behavior, a safe polling rate, future API-key timing, any migration/deprecation schedule, and whether a Replit-hosted backend is accepted. The inspected contract identifies itself as version 0.0.2 and exposes `/v2` routes, but no migration or endpoint-deprecation policy was found. [[1]](https://api.adsb.lol/api/openapi.json)
- No ADSB.lol-published exemption or interpretation was found for third-party display, normalized observations, or temporary caching; what database the ODbL notice refers to and how individual aircraft contents are covered also need clarification. [[1]](https://api.adsb.lol/api/openapi.json) [[4]](https://www.adsb.lol/privacy-license/) [[6]](https://opendatacommons.org/licenses/odbl/1-0/)
- Freshness/latency expectations; `seen`/`seen_pos` units and stale cutoffs; geographic coverage, missing-aircraft behavior, outage policy, and how MLAT/TIS-B flags should be displayed.

### Requires provider confirmation

Before any integration, Signalwatch needs written answers on production/public-map permission; attribution and source/license links; ODbL treatment of normalized and cached observations; permitted cache duration; numeric limits and acceptable polling; current and planned API-key/account/feeder requirements and transition timing; public/commercial application restrictions; and acceptance of a server-side Replit consumer. Provider contact is listed as `info [at] adsb.lol` on its privacy/license page. No message was sent. [[1]](https://api.adsb.lol/api/openapi.json) [[4]](https://www.adsb.lol/privacy-license/) [[6]](https://opendatacommons.org/licenses/odbl/1-0/) [[27]](https://raw.githubusercontent.com/adsblol/api/main/README.md)

Draft questions (not sent):

1. Is public display of ADSB.lol aircraft positions on Signalwatch’s globe/map permitted, including periodic automated refresh?
2. What attribution text, placement, and links to ADSB.lol and the ODbL are required?
3. Does ODbL apply to normalized or temporarily cached Signalwatch observations, and could Signalwatch’s data store trigger a derivative-database/share-alike duty?
4. May Signalwatch cache observations temporarily, and what retention limit applies?
5. What numeric quotas, burst limits, or polling intervals apply to public applications and server-side caching?
6. Is a key or feeder/account required now or planned, and what transition notice/timing should production applications expect?
7. Are public-facing or commercial applications restricted, and is a Replit-hosted backend an acceptable consumer?
8. What do `seen` and `seen_pos` mean, and are there freshness, stale-position, coverage, or outage thresholds Signalwatch should apply?

## Recommendation

If Signalwatch later pursues ADSB.lol, request written provider confirmation using the questions above before implementation. The OpenAPI specifically asks production users to contact the operator and notes a future feeder-linked API key; this research did not contact the provider. Until the display, licensing/data-handling, and rate-limit questions are resolved, do not integrate. [[1]](https://api.adsb.lol/api/openapi.json) [[4]](https://www.adsb.lol/privacy-license/) [[6]](https://opendatacommons.org/licenses/odbl/1-0/) [[27]](https://raw.githubusercontent.com/adsblol/api/main/README.md)

Keep OpenSky as a secondary research candidate only if its terms can be reviewed and its approved API route is reachable from the actual API-server environment. At one credit per small bounding-box request, a five-minute interval fits the published 400-credit/day anonymous quota for one box before other use of the IP bucket, but the observed timeout and hyperscaler warning remain material. Do not use ADS-B Exchange data on a public map without written distribution permission. FlightAware is worth a quote only if its documented plan and endpoint support the intended public B2C map and location query. [[11]](https://openskynetwork.github.io/opensky-api/rest.html) [[12]](https://raw.githubusercontent.com/openskynetwork/opensky-api/master/README.md) [[14]](https://opensky-network.org/api/states/all?lamin=51.45&lomin=-0.15&lamax=51.55&lomax=0.05) [[21]](https://www.adsbexchange.com/acceptable-use-policy/) [[25]](https://www.flightaware.com/commercial/aeroapi/)

## Limitations

Research was conducted on 2026-09-30. No API keys, account credentials, provider contact, access-control bypass, application changes, or deployment changes were used. One unauthenticated ADSB.lol point query succeeded from the research workspace, but this does not establish reachability from the running API server or production permission. The web research service returned HTTP 402; that is a research-tool outcome, not an ADSB.lol response. Direct first-party HTTPS captures were inspected and saved under `research/sources/`. OpenSky terms, Airplanes.live terms and API contract, adsb.fi’s API contract, ADSB.lol production/public-display and ODbL application, numeric rate limits, freshness expectations, and exact FlightAware location-query permissions remain unresolved.
